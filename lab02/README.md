# Лабораторна робота №2 — React Native

> **Тема:** Побудова вкладеної навігації та оптимізація відображення великих списків у React Native із використанням компонентів `FlatList` та `SectionList`.

## Інструкція запуску

### Передумови
- Node.js 18+
- Expo CLI (`npm install -g expo-cli`)
- Expo Go на смартфоні **або** Android/iOS емулятор

### Кроки

```bash
# 1. Клонувати репозиторій
git clone https://github.com/MobileLabsRN2026/lab2.git
cd lab2

# 2. Встановити залежності
npm install

# 3. Запустити
npx expo start
```

Відскануйте QR-код у Expo Go (iOS / Android) або натисніть `a` (Android emulator) / `i` (iOS simulator).

## Опис реалізованого функціоналу

### 📰 Екран новин — `FlatList`

| Функціонал | Деталі |
|---|---|
| **Pull-to-Refresh** | Жест потягування донизу імітує мережевий запит (`setTimeout` 1.5с), перезавантажує список |
| **Infinite Scroll** | `onEndReached` + `onEndReachedThreshold={0.5}` — підвантажує по 10 нових елементів |
| **ListHeaderComponent** | Заголовок списку з назвою та підзаголовком |
| **ListFooterComponent** | Спінер завантаження під час підвантаження нових даних |
| **ItemSeparatorComponent** | Відступ між картками |
| **Оптимізація** | `initialNumToRender=8`, `maxToRenderPerBatch=10`, `windowSize=5`, `removeClippedSubviews` |

Drawer Navigator

## Висновки (контрольні запитання)

### 1. Чим відрізняється `FlatList` від `ScrollView`?

`ScrollView` рендерить **усі** дочірні елементи одразу при монтуванні, що при великій кількості елементів призводить до надмірного споживання пам'яті та гальмування. `FlatList` використовує **віртуалізацію** — рендерить лише елементи, які зараз видимі на екрані, а решту вивантажує з пам'яті. Це робить `FlatList` оптимальним вибором для будь-якого списку з більш ніж 10–20 елементами.

### 2. Що таке віртуалізація списків?

Віртуалізація — це техніка оптимізації, при якій у DOM/нативному дереві одночасно існує лише **невелике вікно** (window) реально відрендерених елементів навколо поточної позиції скролу. Елементи, що виходять за межі вікна, **вивантажуються** з пам'яті, а їх місце займають порожні заповнювачі. Під час прокрутки компоненти **перевикористовуються** (recycling), що економить пам'ять і CPU.

### 3. Як здійснюється передача параметрів між екранами?

Параметри передаються другим аргументом функції `navigate`:
```js
navigation.navigate('Details', { item });
```
На цільовому екрані вони доступні через `route.params`:
```js
const { item } = route.params;
```
Для динамічного заголовка параметри доступні прямо в `options`:
```js
options={({ route }) => ({ title: route.params.item.title })}
```

### 4. Що таке вкладена навігація?

Вкладена навігація — це ситуація, коли один навігатор є **дочірнім екраном** іншого навігатора. У цій роботі `Stack Navigator` (з `MainScreen` і `DetailsScreen`) вбудований як один із пунктів `Drawer Navigator`. Це дає можливість поєднувати різні патерни навігації в одному застосунку і зберігати стан кожного навігатора незалежно.

### 5. У яких випадках застосовується `SectionList`?

`SectionList` застосовується, коли дані мають **групову структуру**: контакти за алфавітом, продукти за категоріями, повідомлення за датою тощо. На відміну від `FlatList`, `SectionList` приймає масив об'єктів `{ title, data }` і автоматично рендерить заголовки секцій (`renderSectionHeader`), підтримує sticky-заголовки. При цьому зберігаються всі переваги віртуалізації `FlatList`.
